# WeGo On Time

**Are Nashville's buses on time?** A collector reads WeGo Public Transit's own live GPS feed every
30 seconds, works out when each bus actually left each timepoint, and compares that with the
published schedule. The results are on a page anyone can read, by route, time of day and stop.

**Live site:** https://nathanaelhub.github.io/wego-on-time/

Riders know their bus is "always late", and the agency reports a systemwide number. This measures
it route by route, from WeGo's own public data, with the method and the raw counts open, so the
number can be checked rather than argued about.

## How it's measured

| Step | What happens |
|---|---|
| Collect | Every 30 s, WeGo's [GTFS-Realtime](https://gtfs.org/realtime/) vehicle positions: each bus, the trip it's serving, where it is, and when it reported. Four GitHub Actions shifts of about 5¼ hours cover the service day. |
| Match | Each trip's reports are walked in time order against its **timepoints** in stop order, so a loop route passing the same corner twice is matched to the right visit. |
| Time | The bus is at a stop while within 100 m. Its **departure** is the last report at the stop plus half the gap to the next; at the end of a line it's the **arrival**. |
| Score | Delay = observed − scheduled. **On time = no more than 1 minute early and no more than 5 minutes late.** At the end of a line only lateness counts. |
| Report | Percentages with 95% (Wilson) ranges; routes and stops with fewer than 100 observed departures aren't ranked. |

What's deliberately left out, and why:

- **Only timepoints are scored.** WeGo's schedule marks some stops as timepoints (about 4 per trip);
  times at the others are interpolated by scheduling software and aren't promises.
- **A pass seen through a gap of more than 2 minutes between reports isn't scored**: the bus could
  have been anywhere in between.
- **A "delay" of more than an hour is dropped** as a trip mislabelled in the feed, not lateness.
- **Coverage is reported, not assumed.** The page says how many of the scheduled trips on
  collection days produced at least one scored timepoint.

**The on-time definition.** WeGo's own definition wasn't found published. 1 minute early to 5
minutes late is the range a Transportation Research Board study found matches most US agencies'
definitions. The thresholds are settings in `src/wego_on_time/report.py`.

## Data

- `data/arrivals/YYYY-MM-DD.csv.gz`: one row per scored timepoint departure (route, trip, stop,
  scheduled and observed time, delay, bus), committed after every shift.
- `data/scheduled_trips.json`: how many trips the schedule had each collection day (the coverage
  denominator).
- Raw positions from each shift are kept for 30 days as a workflow artifact, so any scored event
  can be checked against the GPS reports behind it.

Sources: WeGo's [GTFS-Realtime vehicle positions](http://transitdata.nashvillemta.org/TMGTFSRealTimeWebService/vehicle/vehiclepositions.pb)
(served over http only) and [static GTFS schedule](https://www.wegotransit.com/GoogleExport/google_transit.zip).
Not affiliated with WeGo Public Transit.

## Stack

- **Python 3.11+** with [uv](https://docs.astral.sh/uv/); one dependency, `gtfs-realtime-bindings`
- **GitHub Actions** for the collection shifts, scoring, and the Pages deploy
- **Static HTML** generated by Python; no JavaScript

## Run

```bash
cd wego-on-time
uv sync
uv run wego collect --hours 0.5 --out positions.csv   # record 30 minutes of positions
uv run wego process positions.csv                     # score timepoints into data/arrivals/
uv run wego site                                      # build _site/
uv run pytest -q                                      # tests on hand-built GPS tracks
```

## Limits

- GPS is noisy near tall buildings, and a bus can stop short of or past the stop's mapped point;
  the 100 m pass radius and the "within 25 m of its closest point" dwell rule absorb most of that.
- Scheduled workflows on GitHub can start late or be skipped under load, and are paused if a
  repository sees no activity for 60 days; gaps show up as lower coverage, not as wrong numbers.
- Shift times are set for Central Standard Time; under daylight time each starts an hour earlier.
